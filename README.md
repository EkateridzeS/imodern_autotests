# UI-автотесты iModern

Учебный проект: Python, Playwright, pytest, Allure. Адаптация ручных кейсов OGOGOHOME к iModern по наблюдениям от 24.11.2026. Вход только по email и паролю (по ручной проверке); телефон как идентификатор не поддерживается. Видимая CAPTCHA не обнаружена до последнего шага; скрытая CAPTCHA и итоговый экран заказа пока не проверены. При обнаружении CAPTCHA остановить тестирование и заменить сайт по заданию, не обходить защиту.

## Открытие в PyCharm (Mac)
1. Распаковать ZIP. File → Open → выбрать папку `imodern_autotests`.
2. Settings → Project → Python Interpreter: выбрать уже используемое окружение с практики либо отдельное venv. Рекомендуется Python 3.11/3.12. В Terminal проверить `python -m pip show playwright pytest allure-pytest python-dotenv`. Если окружение не совпадает с зафиксированными версиями, лучше создать отдельное окружение и установить `python -m pip install -r requirements.txt`. При отсутствии браузера: `python -m playwright install chromium`.
3. В Terminal из корня проекта выполнить `cp .env.example .env`. В локальном `.env` указать TEST_EMAIL, TEST_PASSWORD, TEST_NAME, TEST_PHONE выделенного тестового аккаунта. Не передавать этот файл и не коммитить его. По умолчанию AUTH_PATH и PROFILE_PATH — `/personal/profile/` (адрес из ручной проверки); при необходимости уточнить по адресной строке, например `/auth/` для входа.
4. `python -m pytest --collect-only -q` — ожидается 7 наборов (6 авторизации + 1 E2E).
5. `python -m pytest autotest/test_auth.py -v --clean-alluredir` — сначала авторизация.
6. `python -m pytest -m e2e -v --clean-alluredir` — сценарий до финальной кнопки. Использовать только выделенный аккаунт: корзина очищается. Итоговый статус SKIPPED, если реальный заказ не разрешен. Это не завершенный E2E.
7. `python -m pytest -v --clean-alluredir` — общий запуск.
8. `allure --version` — проверить наличие Allure CLI. Если нет, на Mac с Homebrew можно выполнить `brew install allure`; зафиксировать фактическую версию CLI в документации перед сдачей. `allure serve allure-results` — открыть отчет; `allure generate allure-results --clean -o allure-report` — сохранить отчет.

## Структура
- core — настройки, изолированная сессия, логирование, безопасные шаги и диагностика.
- ui — Page Object, CSS-селекторы/XPath, BaseElement, ожидания Playwright.
- autotest — тестовые сценарии, параметризация.
- data/cases.json — безопасные параметры и адаптированные ID.
- conftest.py — фикстуры и диагностика ошибок.

## Ограничения и первый запуск
Код синтаксически проверен, но не запускался с реальным аккаунтом и браузером на iModern. Локаторы предварительные, особенно форма входа, корзина, удаление, количество, цена, финальный экран заказа. Сайт может показывать разные версии интерфейса. При первом падении уточнить DOM через DevTools (Inspect) и исправить соответствующий Page Object, не менять ожидаемый результат наугад. Проверка CAPTCHA — эвристическая, не доказывает ее отсутствие. До подтверждения отсутствия CAPTCHA и разрешения магазина не считать сайт окончательно пригодным.

Финальный клик отключен. Только после согласования тестовых заказов с магазином либо на предоставленной тестовой среде можно поставить обе настройки ALLOW_ORDER=true и ORDER_APPROVED=true. Не запускать повторно после неопределенного результата отправки, сначала выяснить статус заказа. Никаких оплат. Проверки подтверждения и номера предварительные и должны быть адаптированы к фактическому экрану; если данные в истории заказов, реализовать переход в нее.

Логи записывают только имена действий, ID и типы ошибок. В Allure не передаются реальные значения логина/пароля. Скриншоты на форме входа маскируют поля и текст; на страницах с возможными персональными данными сохраняется причина отсутствия скриншота. Не включать Playwright tracing, видео или отладочные логи API при использовании реальных контактов. Не публиковать результаты до проверки на персональные данные.
